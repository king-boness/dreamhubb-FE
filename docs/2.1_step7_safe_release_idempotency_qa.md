## Step 7 (Contribution / Top up) — Safe-first release QA checklist

### Idempotency (double click / retry)
- **Double click on “Top up” confirm**: only **one** token transfer happens; subsequent duplicate request returns same result.
- **Double click on “Help accomplish / Help to fulfill” submit**: only **one** comment is created; subsequent duplicate request returns same result.
- **Refresh page during a pending request**:
  - clicking again uses the **same idempotency key** (stored in `localStorage`) and does **not** create duplicates.

### Atomicity (backend)
- **Insufficient balance**: nothing changes (no user token decrement, no post token increment, no notification).
- **Network failure / 500**: FE does **not** optimistically deduct tokens; UI shows error + allows retry.

### Post-success sync
- **After success**:
  - **user token balance** in FE updates from BE response
  - **post detail tokens** refreshes (re-fetch)
  - **notifications unread count** refresh is triggered (best-effort)
