## Step 7 (Contribution / Top up) — Safe-first release QA checklist

### Idempotency (double click / retry)
- **Double click on “Top up” confirm**: only **one** token transfer happens; subsequent duplicate request returns same result.
- **Double click on “Help accomplish / Help to fulfill” submit**: only **one** comment is created; subsequent duplicate request returns same result.
- **Refresh page during a pending request**:
  - clicking again uses the **same idempotency key** (stored in `localStorage`) and does **not** create duplicates.
- **Key lifecycle**:
  - key is **scoped** by action + postId (+ userId when available)
  - key is **cleared on success (200/201)** so the next action gets a new key
  - key is **cleared on definitive fail (4xx/5xx)**
  - key is **NOT cleared on network fail** (no response) to allow retry/refresh with the same key

### Atomicity (backend)
- **Insufficient balance**: nothing changes (no user token decrement, no post token increment, no notification).
- **Network failure / 500**: FE does **not** optimistically deduct tokens; UI shows error + allows retry.
- **Lock ordering**: donor row is locked first, then post row (`lockForUpdate`) to reduce deadlock risk.
- **Unique-constraint race**: if two requests with the same idempotency key race, BE returns the existing `response_payload` snapshot (HTTP 200) without extra DB changes.

### Post-success sync
- **After success**:
  - **user token balance** in FE updates from BE response
  - **post detail tokens** refreshes (re-fetch)
  - **notifications unread count** refresh is triggered (best-effort)

### Stuck loading prevention (frontend)
- **Top up**: `donateLoading` is reset in store `finally` even if request throws.
- **Help submit**: `submitting` is reset in `finally` even if request throws.

### How to test manually (quick)
- **Double click** on CTA (top up confirm / help submit) → only 1 transaction/comment created.
- **Slow network** (DevTools throttling) → CTA stays disabled during request, then re-enables on completion.
- **Refresh mid-flight** → retry uses same idempotency key (no duplicates).
- **Force 4xx** (insufficient tokens / donate to own post) → clear key + show friendly error, allow retry after fixing input.
